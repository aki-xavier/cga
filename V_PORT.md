# cga (V port)

V (`vlang`) 移植 of the **cga** project — 5D Conformal Geometric Algebra core +
MLX/Metal GPU ray tracing — depending on the [`mlx-v`](https://github.com/)
bindings at `~/code/mlx-v`.

> The original Python source has been renamed `cga/` → `cga_py/` (a git-tracked
> rename) so the V module can own the `cga` name without the Python package
> directory shadowing `import cga`. Revert with `git mv cga_py cga` if needed.

**Demos** — all ported and building: `examples/demo_engine.v`,

`demo_engine.v` and `demo_kinematics.v` assemble their PNG frames into an
animated `.gif` in V (`gif.v`).
They render correctly but are slower than the Python reference (~3 s/frame vs
~30 ms) — the V renderer recurses full-frame for refraction and does not yet
free MLX intermediate handles.

## Architecture decisions

- **Flat module.** All V files are `module cga` at the repo root (mlx-v's
  convention). V submodules + the Python `cga/` package collided, so the module
  is kept flat.
- **The algebra core is plain V `[32]f64`**, not MLX arrays. The 32-component
  geometric product runs on the CPU in double precision (strictly more accurate
  than the Python default float32; `set_precision` is kept as a compatibility
  no-op). The geometric-product table is byte-identical to the Python's,
  generated by `gen/gen_tables.py` into `multivector_tables.v`.
- **`mlx-v` is used where it matters** — the per-pixel render kernel
  (`renderer.v`, `geometry_ops.v`, `shading.v`). V has no `Array`-scalar
  operator overloads, so `mlx_util.v` provides `s_add`/`s_mul`/`s_clip`/…
  free-function helpers.
- **Primitives are plain `Multivector` values** (a motor is also just a
  multivector), so `op`/`ip`/`dual`/`meet` compose freely without a type
  hierarchy.

## Build

Requires V 0.5.x, macOS with Apple Silicon, and `mlx-c` (Homebrew) plus the
`mlx-v` repo — see `~/code/mlx-v/README.md`.

```sh
# one-time: link mlx-v into this project's module path
ln -s ~/code/mlx-v .vmodules/mlx

make test        # run the V test suite
make run         # render the smoke scene → artifacts/render_smoke.ppm
```

(`make` targets set `VMODULES=$(CURDIR)/.vmodules`; if calling `v` directly,
prefix the same env var.)
